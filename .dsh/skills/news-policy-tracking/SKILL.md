# 新闻联播政策追踪

把《新闻联播》读成「行业影响 + 可验证判断」，并长期对账。

**真相在文件里，不在对话里。** 任何时候先读工作区的文件，再动手。

## 五条铁律

1. **不停在「读新闻」上** —— 复述条目等于没做工作。每条都必须回答「所以呢」。
2. **必须写出答案** —— 当天至少 1 条**可被证伪**的判断（问题／我的答案／依据／验证方式／时间窗／趋势／置信度）。没有判断的分析是无效分析。
3. **必须持续跟踪** —— 答案入档后每天回看，直到验证、推翻或超期。
4. **必须说人话** —— 专业词第一次出现先解释再用，格式「**人话叫法**（专业叫法是 XX）」。判断标准：念给一个不看财经新闻的人，他听得懂吗？术语表见 @templates/术语对照表.md；出现新词必须补进去。
   - **每个信号档案必须有「术语小词典」区块**（专业词 + 人话解释的表格），放在第一节之前。**不要只写声明不写内容** —— 2026-10-21 就出现过 26 个文件里 20 个只有声明没有解释。`scripts/check-consistency.mjs` 会检查这一点。
5. **只追加，不改写历史** —— 证据、答案、个人影响，全部只追加。要修正就另起一条「修正说明」。

## 每日运行流程

1. **抓取**：@scripts/new-daily.mjs（在 D:\自动化任务 下执行 node scripts\new-daily.mjs）
   - 取数降级顺序：页面 meta（cctv-official）→ 页面正文（cctv-page-body）→ 栏目页 → 兜底文件
   - 前两种都算官方源；只有当四种全失败、报「主条目 0 条」时才走人工兜底（搜媒体整理的条目单，并标注「可能不完整」）
   - **绝不编造条目**
2. **核查政策原文**：当天最重要的政策／文件，一律用 web_fetch 打开原文（gov.cn、部委官网、财政部等）核对金额、时间表、指标，不要只依据媒体摘要
3. **写日报**：@daily/YYYY-MM-DD.md —— 三件事（术语翻译→真信号→行业传导→机会窗口→反面）＋行业影响表＋今日答案＋视频候选。**不写「对我的个人影响」**（那属于信号文件）
4. **写答案**：1~3 条可证伪判断；证据不足就如实写「尚不明朗」并说明缺什么
5. **更新信号档案**（见下节）
6. **回填 README 索引**：把当天占位摘要换成真实摘要（≤60 字）
7. **说人话自检**：通读当天产出，确认没有未解释的专业词
8. **推送**：node scripts/gh-api-push.mjs "提交说明"

## 更新信号档案（最容易出错的一步）

(a) 先读 @MANIFEST.md
(b) 新答案 → 复制 @signals/_模板.md 新建 @signals/<事件名>.md，在「证据时间线」写「立档」一节
(c) 有进展 → 只打开相关信号文件（1~3 个），在「证据时间线」**追加**带日期小节：日期 · 来源 · 事实 · 我的解读 · 对判断的影响（维持/增强/减弱/推翻）
(c2) **个人影响同步更新**（三条硬规则）：
  - 证据时间线有更新，就**必须同步检查并更新**「七、对我的个人影响与行动项」
  - **只追加、带日期、绝不覆盖** —— 新内容前加三级标题写日期
  - 行动项**双日期**：新增待办必须填「记录日」+「计划日期」；**改状态不删行**，在原文后追加说明
  - 若确实无变化，也要写一行带日期的「无变化」并说明原因
(d) 判断被改变 → 同步更新文件头部表格的「状态/置信度/最后更新」+ 写「修正记录」
(e) **回填 MANIFEST**（唯一的跨文件同步点，必须做）
(f) 在 @tracking/趋势追踪.md 的「趋势进展日志」末尾追加当天小节，逐条写各信号进展；无进展也写一行「无新进展」
   ⚠️ 写完**必须重新读文件确认这一节真的存在**，不要相信写入返回值
(g) **「新证据」标准**：新的资金／订单／招标／价格／政策文件／产能／企业动作。会议报道、表态、被高层文件「点名确认方向」**都不算**，不得据此上调置信度
(h) **置信度一次最多上调一档**（如 中 → 中高），不要因为「猜对了」就跳到「高」

## 已踩过的坑（务必避开）

| 坑 | 正确做法 |
| --- | --- |
| **写入报成功但内容不在文件里** | 每次写完**重新读取验证**，不信返回值 |
| **改了信号文件却忘记回填 MANIFEST** | (e) 是必做项；交付时要报告「MANIFEST 是否已同步」 |
| **个人影响覆盖历史 / 无日期** | 只追加 + 日期小标题 + 行动项双日期 |
| **信号文件用 ID 当文件名** | **文件名＝事件名**（如「康复护理扩容工程.md」） |
| **专业词不解释** | 先人话、括号补专业词；新词补进术语表 |
| **把「政策点名」当成新证据** | 只在时间线注明「政策确认，非订单证据」，置信度不动 |
| **git reset --hard 覆盖未提交文件** | 用 API 推送后若要对齐历史，**先确认工作区没有未提交内容** |
| **在沙箱里用 git credential fill 取 token** | 拿不到管道输出；改用 P/Invoke 从凭据管理器读 |

## 推送与公开范围

- **公开**：MANIFEST.md、signals/、daily/、templates/、scripts/、README.md
- **不公开**（已写入 .gitignore）：tracking/、templates/examples/、video/、docs/、.gh-token
- **git 通道不通时**：用 @scripts/gh-api-push.mjs（走 GitHub API，已验证可用）
- 推送后**用 GitHub API 从公网侧验证**（文件树），不要只看本地命令返回

## 视频（周更，5~10 分钟）

- 结构：1 条主线深挖 + 2~3 条跟踪 + 1 段对账；上限「1 主线 + 3 跟踪」
- 视觉：政策原文录屏 + 数字卡片 + 时间轴为主；**AI 生成画面只做转场**（渲染中文数字不准，错了会毁掉「精确可核对」的人设）
- 说人话规则同样适用；脚本字数 ÷ 300 字/分钟 ≈ 时长
- 合规：不出现个股代码／买卖建议；标「内容为个人观点」；用 AI 画面/配音则标「含有 AI 生成内容」
- 详见 @video/视频形式定案.md、@video/内容节奏设计.md
