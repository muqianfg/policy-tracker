# 视频是怎么做出来的（给不懂代码的人看）

> 写这份文档的原因：你说"不知道一件事怎么搞的，不用 AI 可能都不会搞"。这句话很实在。
> 所以我把这件事拆到最底层 —— **视频制作只有三样东西**，所有软件都只是在这三样上做文章。

---

## 一、先记住一句话：视频 = 图 + 声 + 时长

不管用什么软件，做视频都是在干这三件事：

| 要素 | 是什么 | 用什么做 |
| --- | --- | --- |
| **图** | 观众看到的东西 | PPT、剪映、截图、任何能出图片的工具 |
| **声** | 观众听到的东西 | 自己录音、AI 念、剪映的"文本朗读" |
| **时长** | 图和声要对上 —— 这张图放几秒，得跟这段话多久说完一致 | 手动拖、或用脚本算 |

**"对上"这件事是整个视频制作里唯一的难点。** 其他都是体力活。

---

## 二、我实际做的 5 步（每步用了什么、为什么）

### 第 1 步：把口播稿切成 7 段

| 项 | 内容 |
| --- | --- |
| **做什么** | 一段话对应一张图。7 段 = 7 张图 |
| **为什么** | 如果一堆字配一张图，观众会觉得静止不动；一段一图，画面就跟着话走 |
| **你手工怎么做** | 用 Word 或记事本，把稿子按意思分成 5~8 段，每段前面标个号 |

> 这一步最关键，也最不需要技术。**分段分得好，视频就成功了一半。**

### 第 2 步：让电脑把文字念出来（配音）

| 项 | 内容 |
| --- | --- |
| **我用的工具** | Windows 自带的语音引擎（Microsoft Huihui，中文女声） |
| **它是什么** | 电脑里本来就装着的一个"念字"程序，不需要联网也不需要花钱 |
| **怎么调用** | 一段 PowerShell 命令，喂文字进去，它吐出一个 WAV 音频文件 |
| **你手工怎么做** | 剪映 → 导入文稿 → 选中文字 → "文本朗读" → 选音色 → 生成。**剪映的音色比这个好听得多** |

**这一步的产出**：7 个音频文件，每个对应一段话。

### 第 3 步：做 7 张图

| 项 | 内容 |
| --- | --- |
| **我用的方法** | 用 HTML 写网页（就是排版），然后用浏览器截图 |
| **为什么用网页** | 网页排版精确 —— 字号、位置、对齐可以写死，不会像 PPT 那样一改就乱 |
| **浏览器怎么截图** | Edge 有个"无头模式"（headless），意思是不打开窗口，直接在后台把网页存成图片 |
| **你手工怎么做** | **用 PPT**：新建 16:9，每页放一句话或一个数字，调好字体，然后"另存为图片" |

**这一步的产出**：7 张 1920×1080 的 PNG 图片。

### 第 4 步：算每张图该放多久

| 项 | 内容 |
| --- | --- |
| **做什么** | 用 ffprobe 量出每个音频的确切秒数（比如 s5 是 54.23 秒） |
| **为什么** | 这就是"对上"—— 第 5 段配音说 54.23 秒，第 5 张图就必须显示 54.23 秒 |
| **你手工怎么做** | 剪映里把配音拖到时间轴，看它的结尾在哪，把图片的边缘拖到同一个位置 |

**这一步是整个流程的核心。** 你手工做的时候，就是在做这件事，只不过是用鼠标拖。

### 第 5 步：合成

| 项 | 内容 |
| --- | --- |
| **我用的工具** | **ffmpeg** —— 一个免费的命令行视频处理软件 |
| **它是什么** | 视频界的"瑞士军刀"。不是剪辑软件（没有界面），但能拼接、转换、压缩、加音轨 |
| **怎么用** | 每个分段：`ffmpeg -loop 1 -i 图.png -i 音.wav -t 秒数 输出.mp4`（把静态图按指定时长配上声音） |
| **然后** | 把 7 个分段按顺序拼成 1 个文件 |
| **你手工怎么做** | 剪映里排好时间轴，点"导出" |

## 三、零代码路径：完全不用脚本，用剪映做同一条视频

**这条路径我建议你先走一遍** —— 走通了你就能理解上面的每一步在干什么。

| 步骤 | 操作 | 耗时 |
| --- | --- | --- |
| 1 | 准备口播稿，按意思分 5~8 段（我可以给你） | 已有 |
| 2 | 剪映新建项目 → 比例选 16:9 | 1 分钟 |
| 3 | 用 PPT 做图：每段一页，大字 + 一个数字或一句话 → 全选导出 PNG | 20 分钟 |
| 4 | 剪映里点"文本朗读"，每段文字生成一条配音 | 10 分钟 |
| 5 | 把图按顺序拖进轨道，每张图的长度拖到和对应配音一样长 | 15 分钟 |
| 6 | 点"识别字幕"，自动生成字幕（这一步脚本做不到） | 2 分钟 |
| 7 | 加背景音乐（剪映有免费音乐库） | 3 分钟 |
| 8 | 导出 | 3 分钟 |

**总计约 1 小时，效果比脚本版更好**（音色更好、有字幕、有转场）。

## 四、两条路怎么选

| | 脚本（我做的） | 剪映（手工） |
| --- | --- | --- |
| **第一次耗时** | 约 2 小时（含装软件、调试） | 约 1 小时 |
| **之后每一条** | **约 3 分钟**（改 JSON，跑一条命令） | 约 1 小时 |
| **音质** | 一般（系统自带语音） | **好**（剪映音色自然） |
| **字幕** | ❌ 没有 | ✅ 一键生成 |
| **转场动画** | ❌ 没有 | ✅ 有 |
| **改一句话** | 改 JSON 重跑，全自动 | 手动重做那一段 |
| **需要懂代码** | 需要（或至少会用命令行） | **不需要** |

### 我的建议

| 情况 | 用哪个 |
| --- | --- |
| 每周 1 条长视频 | **剪映** —— 质量重要，1 小时能接受 |
| 每天 1 条短视频 | **脚本** —— 否则每天 1 小时撑不住 |
| **现在这个阶段（试水）** | **剪映先做 2~3 条**，验证内容对不对，再谈自动化 |

> **关键提醒**：脚本版省的是"重复劳动"，不省"内容创作"。
> 而内容（选题、判断、文案）才是这个号的核心 —— 那部分只能你来定，或者我帮你写。

## 六、如果 AI 明天不能用了，你需要记住的 5 件事

1. **视频 = 图 + 声 + 时长**，任何软件都行，不要被工具绑住
2. **一段话 = 一张图**，这是最简单可靠的结构
3. **图有多长，取决于那段话念多久** —— 这是唯一的"技术活"，但也只是拖一下鼠标
4. **剪映能做完 90% 的事**：配音、字幕、转场、导出，全部免费
5. **语速按 200 字/分钟估**，3 分钟写 600 字

**这些跟会不会写代码没关系。** 代码只是让"重复的部分"变快，不让"内容的部分"变好。

## 八、小米 MiMo TTS 已接通（2026-10-25 晚）

### 关键：Base URL 要按 key 前缀选，选错就 401

> 这是踩了最久的一个坑 —— 先说结论。

| 计费方式 | Base URL | Key 前缀 |
| --- | --- | --- |
| 按量付费 | `https://api.xiaomimimo.com/v1` | `sk-` |
| **Token Plan（订阅制）** | **`https://token-plan-cn.xiaomimimo.com/v1`** | **`tp-`** |
| Token Plan（团队） | `https://token-plan-cn.xiaomimimo.com/v1` | `ttp-` |

**我们的 key 是 `tp-` 开头，所以必须用 `token-plan-cn` 那个域名。**
用 `api.xiaomimimo.com` 会一直返回 `401 Invalid API Key` —— 不是 key 坏了，是域名不对。

### 怎么用

```
# 1) 把 key 写进文件（一行，已 gitignore）
D:\自动化任务\.mimo-key

# 2) 单独测试
node scripts\tts-mimo.mjs "要念的文字" out.wav 冰糖

# 3) 在视频脚本里启用（JSON 里加一行）
"tts": { "provider": "mimo", "voice": "冰糖" }
```

## 十、情绪生硬怎么解决（2026-10-25 晚，关键发现）

### 问题：声音机械、情绪生硬

**原因不是音色不好，是我们一直没用「语气指令」。** 等于让模型按默认的播报腔念字，
再好的音色也会显得平。

### 小米 TTS 提供三种控制手段

| 手段 | 放哪里 | 作用 |
| --- | --- | --- |
| **① 语气指令**（自然语言） | `user` 角色的 content | 控制情绪、速度、角色感、场景。**不会被念出来** |
| **② 风格标签** | `assistant` 正文开头 `(沉稳 干练)` | 整体语气定位 |
| **③ 细粒度标签** | 正文中间任意位置 | 插入吸气、叹气、停顿、轻笑、哽咽等 |

### 已验证：标签不会被念出来

同一句「这是一句测试话。」（7 个字），白桦：

| 版本 | 时长 | 说明 |
| --- | --- | --- |
| 无标签无指令 | 1.76 秒 | 基准 |
| 仅指令 | 2.40 秒 | **指令生效**（变慢、更沉稳） |
| 指令 + `(沉稳 干练)` 标签 | 1.92 秒 | 标签生效（更快更干练），**没被念出来** |

如果标签被念出来，至少要长 1.2 秒。实测只差 0.16 秒 → **标签是控制符，不是文字**。

### 我们用的语气指令（可改）

```
用财经频道主持人跟朋友聊天的口吻。语气沉稳但不冷，带一点温度和好奇；
语速中等偏慢；读到数字和关键术语时放慢并加重；
句与句之间留自然的呼吸停顿，不要像念稿。
```

### 可用标签一览（部分）

| 类别 | 示例 |
| --- | --- |
| 语速节奏 | 吸气 / 深呼吸 / 叹气 / 长叹 / 喘气 / 屏住呼吸 |
| 情绪 | 紧张 / 兴奋 / 疲惫 / 委屈 / 惊讶 / 无奈 |
| 音色特征 | 颤音 / 变调 / 破音 / 鼻音 / 气声 / 沙哑 |
| 哭笑 | 微笑 / 轻笑 / 大笑 / 冷笑 / 哽咽 / 抽泣 |
| 整体语调 | 沉稳 / 从容 / 干练 / 温和 / 严肃 / 亲切 / 清亮 |

**用法**：`(沉稳)正文`，或在正文任意位置插 `(停顿)`。半角括号、全角括号、方括号都行。

## 十一、语速问题（2026-10-25 晚，第二次踩坑）

### 坑：指令里写「中等偏慢」，结果慢了 37%

同一句话（56 字）实测：

| 指令 | 时长 | 语速 |
| --- | --- | --- |
| 不加任何指令 | 10.40 秒 | **323 字/分钟** |
| 「语速中等偏慢」 | 16.48 秒 | **204 字/分钟** ← 慢了 37% |
| 「语速中等偏快」 | 9.44 秒 | 356 字/分钟 |
| 「语速偏快」+ `(语速快)` 标签 | 8.48 秒 | **396 字/分钟** |
| `speed: 1.3` 参数 | 11.20 秒 | 300 字/分钟（效果弱） |

**教训**：不要凭感觉写「偏慢」「适中」。**用标签 `(语速快)` 更可靠**，因为它是离散档位，
而形容词会被模型理解成不同的程度。

### 当前采用的配置

```json
"tts": {
  "provider": "mimo",
  "voice": "白桦",
  "style": "语速快",
  "instruction": "用财经频道主持人的口吻，语气沉稳但带温度。语速偏快、干净利落，不要拖沓，停顿要短。读到数字和关键术语时稍微加重，但不要放慢。像跟人聊天，不要像念稿。"
}
```

### 四个版本的时长对比（同一份 926 字稿子）

| 版本 | 配音 | 时长 | 语速 |
| --- | --- | --- | --- |
| v1 | Windows Huihui | 4 分 36 秒 | 200 字/分 |
| v2 | 小米冰糖（无指令） | 3 分 27 秒 | 269 字/分 |
| v3 | 白桦（「中等偏慢」指令） | 3 分 34 秒 | 259 字/分 |
| **v4 当前** | **白桦（「语速快」+偏快指令）** | **2 分 57 秒** | **313 字/分** |

### 还想更快？两个办法

| 办法 | 效果 | 副作用 |
| --- | --- | --- |
| 改指令为「语速很快」，标签用 `(语速快)` | 约 +50 字/分 | 可能吞字 |
| **ffmpeg atempo 加速**（后期） | 精确可控，如 1.1× → 2 分 41 秒 | 音调不变，但齿音会变尖 |

**atempo 用法**（改 make-video.mjs 第五步）：
```
ffmpeg -i 原视频 -filter_complex "[0:a]atempo=1.1[a]" -map 0:v -map "[a]" -c:v copy 输出.mp4
```

## 十二、排版与动态（2026-10-25 晚，v2 重做）

> 用户反馈原话：**"排版太差，中心感不强，图与图之间没有动态变化"**。

### 一、原版的问题（三个，都可量化）

| 问题 | 具体表现 |
| --- | --- |
| **重心偏左** | 文字从 x=150px 开始，到 x≈1000px 结束 —— **右侧空 770px**，视觉重量压在左边 |
| **无焦点** | 背景纯色，没有任何东西把眼睛拉到画面中心 |
| **硬切** | 7 张图直接拼接，中间没有任何过渡 |

### 二、v2 的改法

#### 1. 构图：改成居中（解决"中心感"）

| 改法 | 技术手段 |
| --- | --- |
| 内容块整体居中 | `.stage{width:1560px;text-align:center}` + flex 居中 |
| **径向光晕**把焦点拉到中心 | `radial-gradient(ellipse 62% 58% at 50% 48%, 金色 13% → 透明)` |
| **细网格 + 中心遮罩**给画面隐形秩序 | 120px 网格 + `mask-image` 向中心渐显 |
| 标题下加**金色短线**做视觉锚点 | `.rule{width:72px;height:4px}` |
| 要点用**编号徽章**替代圆点 | 圆角方块 + 边框 + 金字 |
| 数字用**渐变字**（金到暗金） | `background-clip:text` |

#### 2. 动态：三层（解决"图与图之间没有动态"）

| 层 | 手段 | 参数 |
| --- | --- | --- |
| **页内推拉**（Ken Burns） | ffmpeg `zoompan` | 1.00 → 1.06，**奇偶交替推近/拉远**形成呼吸感 |
| **页间转场** | ffmpeg `xfade` | **`fadeblack`（过黑场）**，0.55 秒 |
| **全局进度条** | ffmpeg `drawbox` | 底部 7px 金线，宽度 `iw*t/总时长` |

### 三、一个关键教训：转场方式要看内容

| 转场 | 效果 | 适合 |
| --- | --- | --- |
| `fade`（交叉淡化） | 两页**同时可见**，文字叠在一起 | ❌ **文字页会糊**（实测 s1/s2 叠成一团） |
| **`fadeblack`（过黑场）** | 先暗下去再亮起来，**任何时刻只看到一页** | ✅ **文字页的正确选择** |

**判断标准：如果两页都有大量文字，就不能用交叉淡化。**

### 四、另外两个排版细节（也是实测踩到的）

| 问题 | 原因 | 修法 |
| --- | --- | --- |
| 编号重复成 `1 ① 五省区…` | 文字里本来就带 ①②③，徽章又加了一遍 | 徽章前**自动剥掉开头的圈码**（正则 `^[\u2460-\u2473]`） |
| 断行留下孤字（末行只剩"单"） | 容器 1240px 太窄 + 字号 53px 太大 | 容器放宽到 **1380px**、字号降到 **50px**、加 `text-wrap:pretty` |

### 一、从 v2 到 v3 的关键升级

| | v2 | **v3** |

### 二、核心技巧：把 CSS 动画冻结在任意时刻

**问题**：Edge `--screenshot` 只能截一帧，没法录动画。

**解法**：给页面加 `?t=秒` 参数，用 JS 把所有动画"倒带"到该时刻并暂停：

```javascript
var t = parseFloat(new URLSearchParams(location.search).get("t") || "3");
var els = [].slice.call(document.querySelectorAll(".a,.af,.al"));
var orig = els.map(e => parseFloat(getComputedStyle(e).animationDelay) || 0);
els.forEach((e, i) => {
  e.style.animationDelay = (orig[i] - t) + "s";   // 负延迟 = 倒带到 t 秒
  e.style.animationPlayState = "paused";          // 冻住
});
```

**踩过的坑**：一开始我用 CSS `body.frozen * { animation-delay: ... !important }` 统一设置，
结果 `!important` 覆盖掉了每个元素自己的延迟（0.18/0.30/0.42…），**所有元素同时入场**，错开效果全丢了。
**必须用 JS 逐个元素设置内联样式**，且 CSS 里不能有 `!important`。

### 三、第二个坑：截帧太慢（13 秒/帧）

| 方案 | 速度 | 7 页 × 23 帧 |
| --- | --- | --- |
| 每帧启动一次 Edge `--screenshot` | **13 秒/帧** | **35 分钟** |
| **CDP 一个实例连续截帧** | **1 秒/帧** | **74 秒** |

做法见 `scripts/render-frames.mjs`：Edge 带 `--remote-debugging-port` 启动一次，
之后用 `Page.navigate` + `Page.captureScreenshot` 循环，**提速 13 倍**。
