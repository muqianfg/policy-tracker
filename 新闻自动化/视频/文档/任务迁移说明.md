# 在指定会话里重建每日任务（操作说明）

## 为什么需要这个文件

DSH 的定时任务是**按会话绑定**的：

- 任务记录存在全局存储（`<用户目录>\.dsh\storages\schedule.json`），但每条任务带一个 `sessionId`，触发时把提醒投递回**创建它的那个会话**。
- `schedule_list` / `schedule_delete` 只能看到、只能操作**当前会话**的任务 —— 跨会话既看不见也改不了（这是 2026-10-09 那次误删的原因）。
- 所以任务"住在哪个会话"由**创建动作发生在哪个会话**决定，创建之后无法迁移。

结论：想让自动化住在某个会话，就必须**在那个会话里**创建任务。

---

## 操作步骤

1. 打开你要作为"自动化之家"的那个会话（例如第一次创建任务的那个会话）。
2. 把下面整段消息发给它（这是**一条完整指令**，不是给我看的）：

```
请执行一次定时任务配置操作：

1. 读取 D:\自动化任务\video\任务提示词.md，把其中的全部内容作为定时任务的提示词（prompt）原文使用。
2. 先调用 schedule_list 查看当前会话已有哪些定时任务：
   - 如果已存在标题为「新闻联播简报 + 趋势跟踪」的每日任务，用 schedule_update 把它的 prompt 替换为上面读取到的内容，不要新建。
   - 如果不存在，用 schedule_create 新建：标题「新闻联播简报 + 趋势跟踪（每日 22:00）」，频率 daily，时间 22:00:00，时区 Asia/Shanghai。
3. 完成后报告：任务的 id、下次触发时间、以及是否发生了新建/更新。
```

3. 收到确认后，告诉我任务 id，我这边会把**其他会话里的重复任务**清理掉（避免同一天跑两遍）。

---

## 关键约定（避免重复与冲突）

| 事项 | 约定 |
| --- | --- |
| 同一时间只允许存在 **1 条**每日任务 | 每次改动前先用 `schedule_list` 检查本会话是否已有 |
| 改提示词用 `schedule_update` | **绝不用"删除+新建"** —— 那会把任务搬到当前会话，造成重复 |
| 跨会话任务不可见是正常现象 | 看不到 ≠ 不存在。要确认全局状态，读 `storages\schedule.json` |
| 提示词必须自包含 | 不要把"我们聊过的内容"当作提示词前提；提示词要引用工作区里的文件（README、playbook、模板） |
| 22:00 前后不要改工作区文件 | 21:45–22:15 之间避免编辑 D:\自动化任务 下的文件，防止与自动运行读写冲突 |
