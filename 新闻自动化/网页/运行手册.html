新闻联播每日简报 · 运行手册

一、这套东西是干什么的

每天 20:30（北京时间）自动执行一次：

  1. 抓取当天 19:00《新闻联播》官方条目单
  2. 把新闻术语翻译成人话（不停在"读新闻"上）
  3. 推演对当天新闻所牵涉行业的影响（视角：自由职业者 / 投资者 / 创业者，寻找机会）
  4. 推演对个人的影响，落到可执行动作
  5. 写下一个可被证伪的答案并落盘 ← 核心步骤
  6. 判断趋势方向，并在之后的每一天持续跟踪这条趋势的进展

  • 确认失败就在日报里写明"本期抓取失败 + 原因"，并只基于可获得的公开报道分析

已知坑

  • 央视页面上 19:00 那期的 meta description 才是完整条目单，21:00 重播页的 description 是空的 —— 脚本已优先选 19:00。
  • 必须用 Node 抓取。Windows PowerShell 5.1 的 Invoke-WebRequest 会把 UTF-8 页面按 Latin-1 读取导致中文乱码（fetch-lianbo.ps1 已弃用）。
  • 本机没有 pwsh，只有 powershell 5.1。

四、执行流程（每天照做）

  1. 跑脚本：node scripts\new-daily.mjs，拿到当天条目单。
  2. 读条目单：10~15 条主条 + 一组联播快讯 + 国际条目。不要逐条复述。
  3. 术语去魅：见 playbook 的术语速查表。
  4. 挑 3 件事深挖：有钱、有政策抓手、有时间表、有新提法的才进。每件走完"术语翻译 → 真信号 → 行业传导 → 机会窗口 → 反面理由"。
  5. 行业影响表：方向 + 钱怎么流 + 时间节奏 + 关注信号。
  6. 个人影响：时间/钱/技能/资源，落到"下周可以做的三件事"。
  7. 写下答案（最重要）：1~3 条，格式见 playbook。宁可写"尚不明朗"，也不要把噪音包装成机会。
  8. 追加跟踪：
    • 新答案 → 写进 tracking\趋势追踪.md 的「答案登记表」
    • 对历史答案的新证据 → 追加到「趋势进展日志」，格式 ### YYYY-MM-DD | T-YYYYMMDD-NN
    • 每天回看最近 30 天未结答案；无新进展也要写一行
    • 满 3 个月做一次「校准复盘」
  9. 交付：把当天简报正文输出给用户，并在结尾说明新增了几条答案、有无历史答案被证据更新或推翻。

五、给自动化用的一句话任务描述

读今天的《新闻联播》，把术语翻译成人话，推演它对新闻所牵涉行业的影响（自由职业者/投资者/创业者视角，寻找机会），推演对我的个人影响，然后写下一个可被证伪的答案并保存，判断趋势方向，并在随后的时间里持续跟踪它。

六、信号档案（signals/）

为什么拆分：原来的 tracking\趋势追踪.md 是单文件，每运行一次就要整份重读，随着时间推移 token 成本线性上升。 现在把每条信号拆成独立文件，并在 MANIFEST.md 里维护一张总表 —— 每次运行只必读 MANIFEST（约 600 tokens），再按需读 1~3 个有变化的信号文件。

文件作用谁读
MANIFEST.md信号总表：状态、趋势、置信度、证据条数、最后更新每次必读
signals/T-YYYYMMDD-NN.md单条信号的完整档案（问题/答案/验证方式/证据时间线/复盘/修正记录）按需读
signals/_模板.md新建信号时复制此模板—
tracking\趋势追踪.md保留为日志与总览（按天看）需要回溯时读

新增信号时：复制 _模板.md → 改名 T-YYYYMMDD-NN.md → 填内容 → 在 MANIFEST 总表加一行。 有新证据时：只在对应信号文件的「证据时间线」追加一节，然后回填 MANIFEST 的「证据条数/最后更新/状态/置信度」。
